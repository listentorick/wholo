# ADR-080 — Help site (`apps/help`): Docusaurus over `documentation/docs`, static on nginx, public

**Status**: Accepted
**Date**: 2026-11-04
**Deciders**: Rick Walsh
**Related**: ADR-048 (live environment k3s), ADR-060 (marketing site)

---

## Context

The `scenario-docs` skill turns task scenarios (`documentation/scenarios/*.md`) into
how-to pages with annotated screenshots by actually doing the task in the running app.
It writes Docusaurus pages (`.mdx`) and images into `documentation/docs/`. Nothing
served them. They need a home that customers and distributors can reach:
`https://help.stocdup.com`.

## Decision

### 1. A new standalone workspace `apps/help` (`@wholo/help`), Docusaurus 3

Docusaurus is the format the skill already writes (front matter, admonitions, relative
image paths). The app is configuration only: `docusaurus.config.ts`, an autogenerated
sidebar, and brand CSS mirroring `apps/www`'s tokens. Like `apps/www` it has no BFF, no
`apps/api` call, no database and no secret.

### 2. Content stays in `documentation/docs`

The docs plugin reads `../../documentation/docs` with `routeBasePath: '/'`, so a page
written as `accept-order.mdx` is served at `/accept-order`. The skill keeps writing where
it does; the app never holds content. The home page (`documentation/docs/index.mdx`,
`slug: /`) is hand-written and is not touched by the skill.

### 3. Broken links and images fail the build

`onBrokenLinks`, `onBrokenAnchors`, and the Markdown link and image hooks are set to
`throw`. The image is built in CI on every push, so a page with a dead link or a missing
screenshot never reaches live. This is also the app's test: it has no logic of its own to
unit-test, so it has no `test:cov` script and does not appear in the coverage table.

### 4. Static build served by nginx

The image is a two-stage build: Docusaurus builds static HTML, and
`nginxinc/nginx-unprivileged` serves it on port 3060 (`/healthz` for probes, long cache on
content-hashed `/assets/`, no-cache on pages). The canonical URL (`HELP_SITE_URL`) is
baked in at build time, as `apps/www` does for its analytics flags; CI passes
`https://help.stocdup.com`.

### 5. Public, drafts included, local search

- **Public**, routed like `www` (an IngressRoute on `ingress.hosts.help`, no health
  allowlist). Pages show demo data only, never real customers.
- **Every page is published**, including those generated from scenarios still marked
  `status: draft`.
- **Search** is `@easyops-cn/docusaurus-search-local`: an index built into the static site.
  No outside service, no key.

## Consequences

- A docs change reaches live the same way as code: push to `master`, bump the `help`
  `sha-` tag in `values.live.yaml`, `pnpm helm:install:live`.
- Live needs a proxied Cloudflare DNS record for `help`. The existing `*.<domain>` edge
  and Origin CA certificates cover it.
- Local dev serves the site at `http://localhost:3060` once `wholo/help:local` is built
  and the deployment restarted. Rebuild after any change under `documentation/docs`.
- Draft pages go live as soon as they are generated; review a scenario before running
  the skill on it if its page should not be public yet.
