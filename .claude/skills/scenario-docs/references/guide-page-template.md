# Guide and overview page templates

Same conventions as [page-template.md](page-template.md) (front matter, generated-file
header, images, callouts, admonitions, tone) unless this file says otherwise. A guide's
page goes where `scripts/relayout.py --where <id>` says (in its audience, usually first
in Getting started), with images in `img/<id>/` next to it. The overview's page is
`<docs_dir>/<id>.mdx`, above the audiences, with no `slug`.

## Guide page

```mdx
---
title: <guide title>
sidebar_label: <guide title>
sidebar_position: <order, if set>
description: <the goal, as one sentence>
custom_edit_url: null
---

{/* Generated by scenario-docs from <scenarios folder>/guides/<id>.md. Edit the guide and regenerate; changes here are overwritten. */}

<intro from the Goal: where the reader starts, and what they'll have at the end. 1–2 sentences.>

## What you'll do

1. <stage 1 title>
2. <stage 2 title>
…

<When the stages are grouped, put each group's name in bold above its stages in this
list ("**Products and prices**"), keeping one numbering. Stage sections stay `## n.`;
groups add no headings of their own there.>

## Before you start

- <the access the reader needs (the persona's reader_role)>

## 1. <stage title>

<why this comes now, from Why now:, folded into the concept where it reads better>

<the concept: the stage scenario's Concept, cut to 1–3 sentences>

<the stage's Explain:, if any, as a sentence or a note admonition>

<what you do: 2–3 sentences summarising the stage, from its route, with the guide's
values and the main on-screen labels in bold. No click-by-click instructions.>

![<what the shot shows>](./img/<id>/<stage-slug>.png)

Step by step: [<stage scenario's page title>](<relative link to its page>)

## 2. …

## You're up and running

<the done-when: what the reader now has, and what it means for them>

![<what the shot shows>](./img/<id>/done.png)

## Next steps

- [<page title>](<link>): <one line on what it's for>

<When Next steps are grouped: one `### <group>` per group, each with its list.>
```

**Concepts lead, instructions follow.** Each stage explains the idea first (the reader
meets it here for the first time), then says briefly what they do and links the how-to
for the detail. If the reader could finish the stage from the summary alone, it's too
long; if they couldn't tell what the stage achieves, it's too short.

**One concept per stage, introduced once.** If a later stage's scenario repeats an idea
an earlier stage explained, refer back to it ("the catalogue you made in step 5")
instead of explaining it again.

**Choices and states, as on a how-to page** (page-template.md): each option a stage has
the reader pick, and each status it shows, gets a clause from the terms file the first
time it appears in the guide, with the alternatives when the reader chooses.

**Screenshots: one per stage**, usually the stage's most telling screen (the filled-in
form, the result), with up to 3 callouts. A stage whose result is plainly visible in
the next stage's shot can go without. Callouts are referenced in that stage's text.

**Links** use the target page's real relative path (`../customers/<id>.mdx` for a page in
a sibling group); relayout.py rewrites them if pages move. A stage whose how-to page doesn't exist yet fails the check;
run that scenario first.

## Overview page

```mdx
---
title: <overview title>
sidebar_label: <overview title>
sidebar_position: <order, if set>
description: <the summary, as one sentence>
custom_edit_url: null
---

{/* Generated by scenario-docs from <scenarios folder>/guides/<id>.md. Edit the overview and regenerate; changes here are overwritten. */}

<the summary>

## Who uses <product>

- **<reader-facing role name>**: <one line>. [<guide title>](<link to their guide>)
…

## <concept name>

<the concept's text, for the audience>

![<what the shot shows>](./img/<id>/<concept-slug>.png)

## <next concept> …

## How it fits together

1. …

## Get started

- [<guide title>](<link>)
```

**Role names are the reader's,** never persona ids: "Owner", "Customer", "Driver".

**Screenshots** only for concepts with a `Screen:`, one each, annotating the one or two
things on screen that show the concept (a catalogue's product count, a customer's price
list). No instructions: the overview never says what to click.

**Claims.** Every sentence is from the overview file, which is built from the
scenarios' Concept sections. If the tour shows a claim is wrong (the screen says
otherwise), the run fails rather than publishing it.
